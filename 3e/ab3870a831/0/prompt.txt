# Copilot Task: Upgrade Splash Screen with Truecolor TUI Styling

We are upgrading the Rust TUI splash screen to establish a richer visual direction for the game.

---

# Goal

Apply a polished 24-bit truecolor terminal style to the splash screen using our existing Rust TUI stack.

The splash screen should feel closer to a professional terminal app dashboard than a plain ASCII title screen.

Use Ratatui/Crossterm capabilities only.

Do not introduce:

- GUI frameworks
- SDL
- curses directly
- web UI
- image rendering dependencies

---

# Requirements

## 1. Add color capability support

Create a small color capability layer in `game_tui`, preferably under:

```text
crates/game_tui/src/theme/
  capability.rs
  palette.rs
  gradient.rs
```

Implement:

```rust
pub enum ColorMode {
    TrueColor,
    Ansi256,
    Mono,
}
```

For now, default to `TrueColor`, but structure it so terminal detection/fallback can be added later.

---

## 2. Add semantic splash palette

Do not hardcode random RGB values throughout the splash screen.

Create a splash/theme palette with semantic roles.

Example:

```rust
pub struct SplashPalette {
    pub void_bg: Color,
    pub nebula_a: Color,
    pub nebula_b: Color,
    pub star_core: Color,
    pub title_primary: Color,
    pub title_secondary: Color,
    pub accent: Color,
    pub border_hot: Color,
    pub border_cold: Color,
    pub text_muted: Color,
    pub warning: Color,
}
```

Use `Color::Rgb(r, g, b)` for truecolor.

---

## 3. Add gradient helpers

Add helpers for generating color ramps:

```rust
pub fn lerp_rgb(a: Color, b: Color, t: f32) -> Color;

pub fn gradient(
    a: Color,
    b: Color,
    steps: usize,
) -> Vec<Color>;
```

Support only `Color::Rgb` initially.

If non-RGB colors are passed, fall back gracefully.

---

## 4. Redesign splash screen visuals

Update the splash screen so it includes:

- Large stylized game title
- Subtle starfield / nebula background using Unicode glyphs
- Truecolor gradient border or frame
- Version/build info
- “Press Enter to Start”
- Secondary actions:
  - `N` New Game
  - `L` Load Game
  - `O` Options
  - `Q` Quit
- Small footer hint:
  - `? Help`
  - `Tab Cycle`
  - `Esc Back/Quit`

The visual style should use Unicode safely:

```text
█ ▓ ▒ ░ · ✦ ✧ ◆ ◇ ◈ ▀ ▄ ─ │ ╭ ╮ ╰ ╯
```

Do not rely on emoji for core layout because terminal support varies.

---

## 5. Add an empire/logo preview area

Since we want to revisit empire logos, add a small placeholder “signal/emblem” panel on the splash screen.

Example:

```text
╭─ SIGNAL GLYPH ─╮
│   ◈╱╲◈         │
│   ╲██╱         │
│   ╱██╲         │
│   ◈╲╱◈         │
╰────────────────╯
```

This should be rendered as a reusable helper/widget if practical, not embedded as one-off text.

Create a simple enum or struct that can later become data-driven:

```rust
pub struct EmpireEmblemPreview {
    pub primary: Color,
    pub secondary: Color,
    pub accent: Color,
}
```

---

## 6. Keep architecture clean

The splash screen must remain UI-only.

Do not mutate game state directly from rendering code.

Input handling should continue to emit commands/actions through the existing app flow.

---

## 7. Resize behavior

The splash screen must render acceptably at:

- 80x24 minimum
- 120x36 preferred
- wider terminals

If the terminal is too small, show a compact fallback:

```text
FARSPACE
Press Enter
```

(or the current canonical game title if different)

---

## 8. Accessibility/fallback

Add a simple path for future fallback modes:

- Truecolor
- 256-color
- monochrome/high-contrast

Do not fully implement all modes yet, but avoid making the splash impossible to degrade later.

---

## 9. Tests / validation

Add lightweight tests where appropriate:

- gradient interpolation returns expected colors
- splash render does not panic at small sizes
- splash render does not panic at normal sizes

If snapshot tests already exist, update or add one.

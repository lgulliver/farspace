# Trade Networks and Civilian Shipping v1

Trade Networks v1 adds a deterministic derived trade-route model that makes the
galaxy feel economically alive without individual freighter micromanagement.

## Goals

- Connected colonies generate trade value based on population and development.
- Trade routes are visible and strategically meaningful on the Sector Map.
- Blockades, war zones, hostile fleets, and out-of-supply systems disrupt routes.
- Trade value contributes to empire credits income.
- AI doctrines value trade hubs and safe routes.
- Deterministic, no global RNG, no wall-clock logic.

## Non-Goals (v1)

- Manual freighter control or civilian ship tactical movement.
- Commodity markets, dynamic prices, or import/export goods.
- Real-time pathing or per-ship cargo simulation.
- Trade route micromanagement — routes are fully derived each turn.
- Piracy system (reserved for a future slice).
- Trade Accord treaty type (not yet implemented).

## Data Model

### TradeRoute

A deterministic derived connection between two colony systems within an empire.
Generated each turn from existing state — never stored manually.

```
TradeRoute {
    from: StarId,
    to: StarId,
    value: i64,          // credits/turn generated by this route
    disrupted: bool,     // true if any disruption factor applies
    disruption_reason: Option<TradeDisruptionReason>,
}
```

### TradeDisruptionReason

```
TradeDisruptionReason {
    Blockade,
    WarZone,
    HostileFleetPresence,
    OutOfSupply,
}
```

### GameState additions

```
empire_trade_routes: BTreeMap<EmpireId, Vec<TradeRoute>>
  — derived each turn, cached for UI/reports/events.

empire_trade_income: BTreeMap<EmpireId, i64>
  — total trade credits per empire for current turn.
```

Both caches are **derived**, not authoritative. They exist for performance and
for detecting transitions (disrupted ↔ restored) between turns.

## Trade Value Formula

Per-route base value:

```
base = sqrt(population_a × population_b) × TRADE_BASE_VALUE_PER_POP
```

Where:
- `population` = colony population (0 if no colony on that endpoint)
- `TRADE_BASE_VALUE_PER_POP` = 1 (balance constant)

Modifiers (multiplicative, applied in order):

| Modifier | Factor | Condition |
|---|---|---|
| Development bonus | +10% per Fabrication Yard on either endpoint | |
| Sector hub bonus | +25% if route connects a sector hub or capital | endpoint has shipyard or supply hub |
| Tech bonus | +15% if empire has `Trade Route Administration` | empire-level tech |
| Strategic resource | +15% per connected resource that has trade value | per strategic resource accessible |

Route value is summed across all routes for total empire trade income.

Only routes with `value > 0` are stored. Routes are ordered deterministically
by `(from, to)` ascending.

### Empire Trade Income

```
empire_trade_income = Σ route.value for all routes
```

Trade income is added to empire credits during the economy phase of
`process_end_turn`, before fleet maintenance deductions.

## Trade Route Derivation

Routes are derived from the same connectivity graph used for colony supply:

1. For each empire, compute the set of connected colony systems using
   `stars_have_trade_link()` (hyperspace lanes + distance thresholds).
2. For each pair of distinct systems in that connected set, compute route value.
3. Evaluate disruption for each route.
4. Sort routes by `(from, to)` for determinism.
5. Cache in `empire_trade_routes` and `empire_trade_income`.

Only pairs where **both** endpoints have colonies are considered.

## Disruption Rules

Each route is evaluated for disruption factors:

| Disruption | Effect | Detection |
|---|---|---|
| **Blockade** | Value × 50% | Either endpoint colony is blockaded |
| **Out of Supply** | Value × 50% | Either endpoint colony is isolated |
| **War Zone** | Value × 80% | Empire is at war with any other empire |
| **Hostile Fleet** | Value × 75% | Hostile/war fleet present at either endpoint star (idle or in transit) |

Multiple disruption factors stack multiplicatively.
If any disruption applies, `route.disrupted = true`.

## Event Emissions

Each turn after trade computation:

- `TradeRoutesComputed { empire, route_count, total_value, disrupted_count }`
  — emitted once per empire.
- `TradeRouteDisrupted { empire, from, to, reason }`
  — emitted when a previously-connected route becomes disrupted.
- `TradeRouteRestored { empire, from, to }`
  — emitted when a previously-disrupted route becomes operational again.

Transition detection compares current routes against the previous turn's cache
(`last_trade_routes` / `last_trade_disrupted` on the Engine).

## Integration Points

### Colony Supply / Connectivity

Trade routes reuse the existing `recompute_colony_supply()` BFS graph. A route
exists between two colony systems iff both are reachable from the same trade hub
via the supply network.

### Economy / Yield Model

Trade income appears as a new component of colony yields and empire credit income:

- Each colony's `trade_income` = sum of route values for routes where this colony
  is an endpoint.
- `ColonyYield.credits` already includes colony income; trade is added separately
  in the engine during `process_end_turn`.
- `EmpireEconomySummary` gains a `trade_income` field.
- `Event::EconomySummary` gains a `trade_income` field.
- `Event::ColonyProduced` gains a `trade` field.

### Diplomacy

- War sets `WarZone` disruption factor on all routes.
- Future: `TradeAccord` treaty type would boost trade value between signatories.
- Diplomacy screen shows trade income when intel level permits.

### Blockades

- Blockaded colonies have 50% route value from all their trade routes.
- Blockade detection already exists in `recompute_colony_blockade()`.

### AI

- **Merchant** doctrine: values systems with high trade potential for colony
  targeting and defense.
- **Militarist** / **Imperial** doctrines: during war, may target systems with
  high trade value for disruption.
- **Isolationist** doctrines: prioritize internal trade security, assign
  TradeProtection fleet roles to protect high-value routes.

### Sector Governance

- `Economic` sector directive may prefer building Fabrication Yards or Supply Hubs,
  which indirectly boost trade value.
- Sector hubs (stars with shipyards or supply hubs) get trade value bonus.

### Victory Conditions

- `Prosperity` victory counts trade income as economic strength.
- No direct victory-path modifier in v1 (trade income already contributes to
  credits, which feeds prosperity metrics).

### Galactic Dispatch

Dispatch items for trade:

| Event | Category | Severity |
|---|---|---|
| Major trade disruption (≥50% routes disrupted) | Trade | Urgent |
| Trade network exceeds threshold | Trade | Notable |

## Save/Load

Trade route caches (`empire_trade_routes`, `empire_trade_income`) are persisted
in GameState for performance and transition detection.

Migration:
- Schema bumped to v39.
- v38→v39 adds new fields with `#[serde(default)]` — passthrough migration.
- Old saves load with empty trade state; first turn computes fresh.

### Sector Map (Trade Overlay)

- New overlay mode on Sector Map activated by `t` key (cycles: None → Resources → Trade → ...).
- Trade routes rendered as dashed lines between connected colony stars.
- Route value displayed on hover/selection.
- Disrupted routes shown in red/dim.

### Empire Overview

- New "Trade" section showing total trade income, route count, disrupted count.
- Colony rows show per-colony trade contribution.

### Colony / System View

- Colony screen shows trade contribution in stats panel.
- System screen shows trade income from this system's routes.

### Diplomacy Screen

- Future: show trade income for known empires when intel permits.
- V1: placeholder showing presence of trade network if empire data is available.

### Turn Report

- Counts disrupted/restored trade routes in end-turn summary.
- Major disruption events logged.

### Help Overlay

- Updated to document trade overlay toggle (`t`), trade icon meanings.

## Determinism Notes

- All trade computation uses ordered collections (BTreeMap, sorted iteration).
- No RNG used in trade route value calculation.
- Route order is deterministic: sorted by `(from, to)`.
- Disruption evaluation depends only on deterministic state.
- Cache is re-derived each turn, never stale-persisted.
- Same seed + same commands = same trade output.
